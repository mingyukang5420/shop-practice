# 요구사항명세서 (MVP)

버전: v1 (MVP)
상태: 확정
작성일: 2026년 7월 31일
기반 문서: 기획_v3 (확정), 0731-practice.pdf (구현 패턴 참고)

## 1. 문서 목적 및 범위

본 문서는 기획_v3에 정의된 전체 요구사항(REQ-001~016) 중 **1차 MVP에서 구현할 범위**를 재정의한다. 인증/인가 기능과 관리자 프론트엔드는 MVP에서 제외하고, 백엔드 REST API(도서/장바구니/주문)만 우선 구현한다. 또한 MVP를 진행하며 발견된 **차별화 요구사항(REQ-017: 동시 주문 시 재고 초과 방지)**을 신규로 추가한다.

## 2. MVP 범위 결정 사항

| 항목 | 결정 | 사유 |
| --- | --- | --- |
| 인증/인가 | 제외 | 실습 MVP 단계에서는 핵심 도메인(도서·장바구니·주문) 검증이 우선이며, 인증은 이후 라운드에 별도 추가 |
| 회원 식별 | 고정 더미 회원 1명(id=1) 사용 | 로그인 없이도 장바구니/주문 흐름을 검증하기 위한 임시 조치. `data.sql`로 시딩하며, 추후 인증 도입 시 요청 컨텍스트에서 실제 회원 식별로 교체 |
| 관리자 프론트엔드 | 제외 | 백엔드 API 우선 검증, UI는 API 안정화 후 별도 진행 |
| 재고 초과 주문 방지 | MVP에 기본 검증 포함, 동시성 강화는 설계만 우선 | REQ-010의 핵심 요구사항이므로 기본형은 필수. 동시 요청 경쟁 상태 방지는 REQ-017로 별도 분리하여 설계 후 다음 라운드에 구현 |

## 3. 요구사항 목록 (MVP 스코프)

| ID | 요구사항 | 상세 설명 | 우선순위 | MVP 포함 여부 |
| --- | --- | --- | --- | --- |
| REQ-001 | 일반 회원가입/로그인 | 이메일/비밀번호 기반 회원가입 및 JWT 로그인 | 필수(전체) | **제외** — 고정 더미 회원으로 대체 |
| REQ-002 | Google OAuth 로그인 | Google 계정으로 소셜 로그인, 신규 사용자는 자동 회원가입 | 필수(전체) | **제외** |
| REQ-003 | 회원 권한 구분 | USER/ADMIN 역할 필드를 두고, JWT에 권한 정보 포함 | 필수(전체) | **제외** — MVP는 모든 API 공개(인증 게이트 없음) |
| REQ-004 | 도서 목록 조회 | 페이징 처리된 전체 도서 목록 조회 | 필수 | **포함** |
| REQ-005 | 도서 상세 조회 | 단일 도서의 상세 정보 조회 | 필수 | **포함** |
| REQ-006 | 도서 검색/필터링 | 제목/저자 키워드 검색, 카테고리 필터링 | 필수 | **포함** |
| REQ-007 | 도서 등록 | 신규 도서 등록 | 필수 | **포함** — MVP는 권한 검증 없이 공개 API로 제공 |
| REQ-008 | 도서 수정 | 도서 정보 수정 | 필수 | **포함** — 상동 |
| REQ-009 | 도서 삭제 | 도서 삭제 | 필수 | **포함** — 상동. 주문 이력 보존을 위해 OrderItem은 스냅샷 데이터를 별도 보관(기능명세서 참조) |
| REQ-010 | 재고 관리 및 주문 수량 검증 | 도서 상세/장바구니에 재고 수량을 안내하고, 사용자가 직접 주문 수량 조절. 재고 이하 수량에서만 주문 처리되며, 초과 시 주문 실패 | 필수 | **포함(기본형)** — 단일 요청 기준 검증. 동시 요청 경쟁 상태 방지는 REQ-017 참조 |
| REQ-011 | 장바구니 담기 | 회원이 도서를 장바구니에 담기 | 필수 | **포함** — "로그인한 회원" 대신 고정 더미 회원 기준으로 동작 |
| REQ-012 | 장바구니 조회/수정/삭제 | 장바구니 내 항목 조회, 수량 수정, 항목 삭제 | 필수 | **포함** |
| REQ-013 | 주문 생성 | 장바구니 항목을 기반으로 주문 생성, 재고 차감 | 필수 | **포함** |
| REQ-014 | 주문 내역 조회 | 본인 주문 내역 목록 및 상세 조회. 주문 상태는 "주문완료" 단일 상태로 관리 | 필수 | **포함** |
| REQ-015 | 관리자 상품 관리 화면 | 관리자 프론트에서 도서 등록/수정/삭제 UI 제공 | 필수(전체) | **제외** — 백엔드 API만 우선 제공 |
| REQ-016 | 관리자 주문 관리 화면 | 관리자 프론트에서 전체 주문 목록/상세 조회 UI 제공 | 필수(전체) | **제외** — 백엔드 API(`/api/admin/orders`)만 우선 제공 |
| **REQ-017** | **(신규/차별) 동시 주문 시 재고 초과 방지** | 여러 요청이 동시에 같은 도서를 주문하더라도 실제 재고보다 많은 수량이 판매(차감)되지 않아야 한다. 장바구니 담기·수정·주문 생성 세 지점에서 재고를 검증하되, 특히 주문 생성 시점에는 동시 트랜잭션 간 경쟁 상태(lost update)로 인한 초과 판매가 발생하지 않도록 원자적으로 처리되어야 한다 | 필수(차별 기능) | **MVP: 기본 검증 포함 / 동시성 강화: 설계 완료, 구현은 차기 라운드** |

## 4. 도메인 용어 정리

| 용어 | 정의 |
| --- | --- |
| Member(회원) | 장바구니·주문의 소유 주체. MVP에서는 인증이 없으므로 `id=1`의 고정 더미 회원 1명만 존재하며 `data.sql`로 시딩된다. 모든 장바구니/주문 API는 이 회원을 암묵적으로 사용한다 |
| Book(도서) | 판매 대상 상품. 제목/저자/카테고리/가격/재고/설명을 가진다 |
| Category(카테고리) | 도서 분류. MVP에서는 카테고리 자체의 CRUD API는 제공하지 않고 `data.sql`로 시딩된 값만 사용한다 |
| CartItem(장바구니 항목) | 회원이 담은 도서와 수량. 가격/재고는 항상 최신 Book 값을 조회하여 응답한다(스냅샷 아님) |
| Order(주문) | 장바구니에서 전환된 주문 단위. 상태는 "주문완료" 단일 값만 존재(취소 기능 없음) |
| OrderItem(주문 항목) | 주문에 포함된 도서와 수량. **주문 시점의 도서명/가격을 스냅샷으로 보관**하여, 이후 도서 정보가 수정·삭제되어도 과거 주문 내역이 변하지 않도록 한다 |

## 5. 비고 (향후 과제)

- REQ-001~003(인증), REQ-015~016(관리자 프론트)은 MVP 검증 이후 별도 요구사항 명세서 개정을 통해 재도입한다.
- REQ-017의 동시성 강화(비관적 락 등)는 실제 인증을 통한 다중 회원 환경이 갖춰진 이후에야 실질적인 가치를 가지므로, 인증 도입과 함께 우선순위를 재검토한다. 상세 설계는 `API명세서.md`와 `기능명세서.md`의 차별 기능 절을 참조한다.
