# 작업 순서 (실습 과제 제출용)

버전: v1
기반 문서: 요구사항명세서.md, 기능명세서.md, API명세서.md
전제: Spring Initializr 스켈레톤 생성 완료 (`skala-shop/`, Spring Boot 4.1.0, Gradle, Java 21 — 의존성: Web/JPA/H2/Validation/Lombok/DevTools/Actuator)

## 진행 방식

아래 순서는 하위 계층(엔티티) → 공통 인프라 → 리소스별 API(Book → Cart → Order → Admin) 순으로, 뒤 단계가 앞 단계에 의존하도록 구성했다. 각 단계 완료 시 체크박스를 표시하며 진행한다.

## 0. 프로젝트 기본 설정

- [x] `application.yml`에 H2 인메모리 DB, `spring.jpa.hibernate.ddl-auto`, H2 콘솔(`/h2-console`) 활성화 설정
- [ ] 패키지 구조 확정 (예: `domain`, `repository`, `service`, `controller`, `dto`, `exception` — 0731-practice.pdf 패턴 참고)

## 1. 도메인 엔티티 (요구사항명세서 4절 도메인 용어 정리 기준)

- [ ] `Member` (더미 회원, id=1 고정 시딩 대상)
- [ ] `Category`
- [ ] `Book` (title/author/category/price/stock/description)
- [ ] `CartItem` (member-book-quantity)
- [ ] `Order` / `OrderItem` (OrderItem은 주문 시점 title/price **스냅샷** 필드 보유 — 기능명세서 2.5, 4.1)
- [ ] Book 삭제 시 OrderItem의 Book FK가 `NULL` 처리되도록 연관관계 설정 (기능명세서 2.5)

## 2. Repository 계층

- [ ] `BookRepository` — keyword(title/author) + categoryId 조합 검색 쿼리 (기능명세서 2.1), 향후 `@Lock(PESSIMISTIC_WRITE)` 적용을 고려한 `findByIdForUpdate` 자리 확보(MVP는 미구현, API명세서 7.2 참조)
- [ ] `CartItemRepository`, `OrderRepository`, `OrderItemRepository`, `CategoryRepository`, `MemberRepository`

## 3. 공통 인프라

- [ ] 공통 에러 응답 DTO (`timestamp/status/code/message/path` — API명세서 1절)
- [ ] `GlobalExceptionHandler` (`@RestControllerAdvice`) — 커스텀 예외 → 에러 코드 매핑: `BOOK_NOT_FOUND`, `CATEGORY_NOT_FOUND`, `CART_ITEM_NOT_FOUND`, `ORDER_NOT_FOUND`, `INSUFFICIENT_STOCK`, `INVALID_REQUEST`, `VALIDATION_ERROR` (API명세서 6절)
- [ ] 페이징 응답 포맷 (`content/page/size/totalElements/totalPages`) 공통 처리
- [ ] `INSUFFICIENT_STOCK` 메시지에 도서명/요청수량/가용재고 포함되도록 메시지 포맷 구현 (API명세서 7.1)

## 4. 더미 데이터 시딩 (`data.sql`)

- [ ] 더미 회원(id=1) 1건
- [ ] 카테고리 시딩
- [ ] 도서 시딩(재고 다양하게 — 재고 부족 테스트용으로 재고 1~2권짜리 포함)

## 5. Book API (요구사항명세서 REQ-004~009, API명세서 2절)

- [ ] GET 목록 (keyword/categoryId 필터 + 페이징) — 존재하지 않는 categoryId는 빈 목록(기능명세서 2.1)
- [ ] GET 상세
- [ ] POST 등록 (Bean Validation 적용, categoryId 존재 검증)
- [ ] PUT 수정
- [ ] DELETE 삭제 (주문 이력 보존 확인)

## 6. Cart API (REQ-011~012, API명세서 3절)

- [ ] POST 담기 — **동일 도서 재담기 시 수량 합산** + 합산 후 재고 검증(기능명세서 3.1, 차별 기능 1단계)
- [ ] GET 조회 — price/stock은 항상 최신 Book 값
- [ ] PATCH 수량 수정 — 재고 재검증(차별 기능 2단계)
- [ ] DELETE 항목 삭제

## 7. Order API (REQ-013~014, API명세서 4절)

- [ ] POST 주문 생성 — 전체/부분(cartItemIds), 트랜잭션 내 전량 재고 검증 후 전체 성공/전체 롤백(차별 기능 3단계, TOCTOU 재검증)
- [ ] 주문 성공 시 재고 차감 + OrderItem 스냅샷 저장 + 대상 CartItem 삭제
- [ ] GET 목록/상세 (더미 회원 기준)

## 8. Admin API (REQ-016 백엔드 부분, API명세서 5절)

- [ ] GET 전체 주문 목록/상세 (회원 필터 없음, 엔드포인트만 분리)
